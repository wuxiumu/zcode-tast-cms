# 02 系统架构设计

## 1. 总体架构

```
┌────────────────┐      ┌────────────────────┐
│  用户端 H5      │      │  管理端 Admin       │   React 18 + Vite + TS
└───────┬────────┘      └─────────┬──────────┘
        │   HTTPS / JSON          │
        └───────────┬─────────────┘
              ┌─────▼─────┐
              │   Nginx   │  静态资源 / 反代 / 上传大小限制 / 图片直出
              └─────┬─────┘
        ┌───────────▼─────────────┐
        │  PHP API (Slim 4, fpm)  │
        │   Controller            │
        │   Service  业务逻辑      │
        │   ├─ FileStore ─────────┼──▶ storage/*.md   分类/标签/素材(内容库)
        │   ├─ RedisStore ────────┼──▶ Redis          任务/凭证/奖励/用户/索引
        │   └─ Upload    ─────────┼──▶ uploads/       图片/视频原始文件
        └─────────────────────────┘
```

三层职责一句话：

- **文件（md）= 内容库**：分类、标签、素材这类「运营录入、低频修改、需要人能直接看」的数据，存 Markdown + YAML frontmatter，一个素材一个文件。
- **Redis = 状态库**：用户、任务、凭证、奖励、索引、计数，高频读写、需要原子操作和过期机制。
- **磁盘 uploads/ = 原始文件**：图片视频，Nginx 直接 serve，PHP 只负责校验和落盘。

## 2. 技术选型

| 层 | 选型 | 版本 | 理由 |
|----|------|------|------|
| API | PHP + Slim 4 | PHP ≥ 8.1 | 微框架零负担，无 ORM 依赖，与「无 MySQL」匹配；备选 ThinkPHP 8（团队若更熟） |
| Redis 客户端 | predis/predis | 2.x | 纯 PHP 无扩展要求；服务器有 phpredis 则优先 phpredis |
| Markdown 解析 | symfony/yaml + league/commonmark | - | frontmatter 用 YAML 解析，正文按需渲染 |
| 用户端 H5 | React 18 + Vite + TS + antd-mobile | - | 移动优先，组件够用 |
| 管理端 | React 18 + Vite + TS + Ant Design 5 | - | 表格/表单场景成熟 |
| 数据请求 | @tanstack/react-query + axios | - | 列表缓存、失效刷新 |
| 鉴权 | JWT（firebase/php-jwt） | - | H5 与 Admin 双端分离签发 |

## 3. 「php + md + redis」的分工与边界

| 数据 | 存储 | 结构 | 写入方 |
|------|------|------|--------|
| 分类 | `storage/categories.md` | 单文件，YAML frontmatter 存列表 | 管理端 CRUD |
| 标签 | `storage/tags.md` | 同上 | 管理端 CRUD |
| 素材 | `storage/materials/mat_XXXXX.md` | 一素材一文件，frontmatter=结构化字段，正文=发布说明 | 管理端 CRUD |
| 用户 | Redis `sc:user:{uid}` | hash | 注册时写 |
| 任务/凭证/奖励 | Redis hash + zset | 见 05 文档 | 用户行为/审核动作 |
| 图片视频 | `uploads/{Y}/{m}/{d}/{uuid}.{ext}` | 文件 | 上传接口 |

**为什么内容库用 md 而不是 json**：运营可直接用编辑器看和改（人工兜底、可 git 管理版本）；结构化字段全在 frontmatter 里，程序解析等价于 json。

**一致性约定**：`storage/` 下的 md 文件是内容库的唯一事实源（source of truth）；Redis 里的素材缓存/索引只是加速层，可随时由 `scripts/rebuild-index.php` 从文件重建。反之，任务/奖励这类状态数据只存在 Redis，**必须开启 AOF 持久化并每日备份**（见 05 文档）。

## 4. 关键设计决策

### 4.1 素材发布 → 索引同步

素材在管理端「上架」时，PHP 做两件事：写 md 文件 + 重建该素材的 Redis 索引（分类 zset、分类×标签 zset）。下架/改标签即删旧索引。**列表页只查 Redis，不扫文件**，保证用户端接口是 O(1)~O(logN)。

### 4.2 领取任务的并发安全

「校验配额 + 唯一领取 + 扣减配额 + 建任务」用一段 Redis Lua 原子完成，杜绝超发（详见 05 文档 §5）。

### 4.3 上传与访问

- 上传走 PHP 接口（校验扩展名/MIME/大小，图片≤10MB×9张，视频≤200MB），文件名用 uuid，禁止原文件名。
- 访问走 Nginx 静态直出；本期不做私有读（截图含个人数据，预留后续加 `internal` + 鉴权跳转）。

### 4.4 双端鉴权

- 用户端 token：`aud=user`，有效期 7d，payload 含 uid。
- 管理端 token：`aud=admin`，有效期 12h；管理员账号密码存 `config/admin.php`（本期管理员 ≤ 3 人，不建用户体系）。
- 中间件按 aud 校验，接口路径天然隔离（`/api/v1/*` vs `/api/v1/admin/*`）。

## 5. 部署拓扑

单机部署，目录规划：

```
/srv/sucaiku/
├── backend/     # PHP 代码
├── frontend/    # 构建产物 dist 由 Nginx 托管
│   ├── h5-dist/
│   └── admin-dist/
├── uploads/     # 上传文件（软链或直接指向 backend/uploads）
└── backup/      # redis dump + storage 打包（每日凌晨）
```

Nginx 要点：

```nginx
server {
    listen 443 ssl;
    root /srv/sucaiku/frontend/h5-dist;        # admin 单独 server 或 /admin 路径
    location /api/    { fastcgi_pass unix:/run/php/php8.2-fpm.sock; ... }
    location /uploads/ { alias /srv/sucaiku/uploads/; expires 7d; }
    location /        { try_files $uri /index.html; }   # SPA history 路由
    client_max_body_size 210m;
}
```

环境变量（`.env`，PHP 侧 Dotenv 加载）：

```
APP_ENV=production
JWT_SECRET=***
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=***
KEY_PREFIX=sc:
UPLOAD_DIR=/srv/sucaiku/uploads
MAX_MATERIALS=100        # 素材数告警阈值，超过即提示启动 MySQL 升级
```

## 6. 安全设计要点

| 项 | 措施 |
|----|------|
| 鉴权 | JWT 双端分离；刷新逻辑本期从简（过期重登） |
| 越权 | 用户端所有任务/凭证接口校验 `resource.user_id == token.uid` |
| 上传 | 白名单扩展名 + MIME 双校验、大小限制、uuid 重命名、图片禁止执行权限 |
| 限流 | Redis 计数限流：登录 5 次/分钟，提交 10 次/小时，领取 20 次/日 |
| 防刷 | 链接全局去重、截图哈希粗查重、每用户日领取上限（详见 07） |
| 传输 | 全站 HTTPS |

## 7. 升级路径（预留，不实现）

**触发条件**（满足其一即启动）：素材总数 > 100；需要跨素材复杂统计/事务；多管理员协作出现写冲突。

**方案**：新增 MySQL，`Repository` 接口已有三个实现位（`FileStore` / `RedisStore` / 未来 `MysqlStore`），内容库写导入脚本 `scripts/import-to-mysql.php` 逐文件解析 frontmatter 入表；任务/奖励历史从 Redis dump 导入。API 层与前端零改动。
