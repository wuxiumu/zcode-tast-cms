│   │   ├── categories.md
│   │   ├── tags.md
│   │   └── materials/
│   │       └── mat_10001.md

定时任务汇总：

| 频率 | 脚本 | 作用 |
|------|------|------|
| 每 5 分钟 | expire-sweep.php | 任务超时过期、释放配额 |
| 每日 03:00 | backup.sh | 备份（保留 14 天） |

## 2. 开发里程碑

### M1 后端骨架 + 内容库（约 3 天）

- 工程初始化、路由/中间件/统一响应/错误码。
- 分类、标签 CRUD（md 文件读写 + Redis 缓存）。
- 素材 CRUD + 上架/下架 + 上传接口 + 索引同步。
- 管理端登录。
- **验收**：用 curl 走通「建分类→建标签→传图→建素材→上架→rebuild-index」；storage 下能看到规范 md 文件。

### M2 用户端核心 API（约 3 天）

- 登录（验证码 mock）、JWT。
- 分类树/标签筛选/任务大厅列表/素材详情。
- 领取（Lua + 多选补偿）、我的任务、提交首发凭证（去重）。
- 过期扫描脚本。
- **验收**：模拟 10 并发领取同一素材，配额不超发；全流程状态机（claimed→submitted→approved）正确。

### M3 管理端前端（约 3 天）

- 素材编辑表单（类型切换、标签多选预留位、奖励规则编辑器）。
- 审核中心（首发/数据两个 tab）、奖励记录、分类/标签管理页。
- **验收**：运营全程不碰命令行完成一条素材从录入到奖励打款的闭环。

### M4 用户端 H5（约 4 天）

- 任务大厅（多选领取）、素材详情（复制/保存）、任务详情（按状态渲染操作区）、提交/补数据表单、奖励记录。
- **验收**：手机浏览器 + 微信内打开全流程可用；驳回→重交、补发 3 轮数据、过期释放三个分支各验一遍。

### M5 流程加固 + 联调（约 2 天）

- 数据凭证审核按快照核算、奖励打款标记、防刷限流全开。
- 备份/重建脚本演练（删 Redis → rebuild 恢复索引）。
- **验收**：按 07 §7 异常对照表逐条演练通过。

总计约 15 个工作日（单人）。

## 3. 待确认问题（开工前最好拍板）

| # | 问题 | 建议默认 |
|---|------|----------|
| 1 | 用户登录方式：短信验证码（需签名/模板备案）还是微信网页授权（需认证服务号）？ | M1 先手机号+图形验证码简化，通道后接 |
| 2 | 奖励打款通道：微信商家转账/支付宝/纯人工？ | 本期人工打款 + 记录，通道字段已预留 |
| 3 | 同一素材是否允许多个用户发布到同一平台？ | 允许（靠配额控制总量），同一发布链接全局唯一已防一稿多领 |
| 4 | 视频号链接不可复制时的凭证形态？ | 引导填「昵称+发布时间」+ 数据页截图，人工核对 |
| 5 | 素材内容是否需要分渠道变体（同素材小红书/抖音文案不同）？ | 本期一个素材一套内容；若需要，可在素材内加 `content_by_tag` 扩展（结构已预留多标签位） |
| 6 | 是否需要邀请码注册制控制用户规模？ | 建议有，`config/app.php` 开关，防上线即被薅 |

## 4. 风险

| 风险 | 缓解 |
|------|------|
| Redis 状态丢失 | AOF everysec + 每日 dump + 奖励流水以审核记录可对账 |
| 截图造假无法技术识别 | 人工审核 SOP + 粗查重 + 封号拒付；成本可控因为量小 |
| 视频号等平台无链接可填 | 凭证字段设计已兼容（链接可空、备注形态，见问题 4，实现时平台按 tag 配置 `url_required`） |
| 单文件 md 被误编辑 | storage 纳入 git；后台保存前做 frontmatter 校验，非法则拒绝写入 |
