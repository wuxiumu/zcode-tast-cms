# 01 需求概述

## 1. 项目背景与目标

运营团队持续产出推广素材（图文、视频+文字），希望引导用户（发布者）将素材自发到小红书、微信视频号等平台，以换取奖励；素材在平台上的真实数据（播放、点赞、评论）越好，追加奖励越多，从而放大内容分发效果。

本系统要解决三件事：

1. **素材资产化**：素材按「分类 + 标签」入库，后台可随时增删改、上下架。
2. **任务分发**：用户按 分类 → 标签(渠道) 找到可发布的素材，多选领取。
3. **效果回收**：发布后回传截图领首发奖励；数据达标后补发截图领追加奖励。

## 2. 角色

| 角色 | 说明 | 使用端 |
|------|------|--------|
| 管理员（运营） | 维护分类/标签/素材、审核凭证、发放奖励、看数据 | 管理端 Admin（PC） |
| 用户（发布者） | 浏览任务、领取、去平台发布、回传截图、领奖励 | 用户端 H5（手机） |

## 3. 核心业务流程

```
运营侧                          用户侧
──────                          ──────
建分类(游戏>蛋仔派对)            
建标签(小红书/视频号…)           
录素材(图文/视频+文字,           
  预留标签位, 配奖励规则)         
素材上架 ──────────────────────▶ 分类下按标签筛选任务列表
                                多选 1,2,3 领取任务
                                查看素材 → 复制文案/保存图片
                                去对应平台发布
                                回 H5 提交 链接+发布截图
审核首发凭证 ──────────────────▶ 通过 → 首发奖励到账
                                (数据达标)补发数据截图
审核数据凭证 ──────────────────▶ 通过 → 追加奖励(可多轮至上限)
```

## 4. 功能需求清单

### 4.1 管理端（Admin）

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| A1 | 分类管理 | P0 | 两级分类（如 游戏 > 蛋仔派对），排序、启停 |
| A2 | 标签管理 | P0 | 渠道标签（小红书/视频号/抖音/快手/B站/微博…），可配「发布引导文案」 |
| A3 | 素材管理 | P0 | 新建/编辑/上下架/删除；类型=图文 或 视频+文字；**预留标签多选位**；配额、每人限领 |
| A4 | 奖励规则配置 | P0 | 首发奖励金额；数据奖励档位（指标/阈值/金额）；补发轮次上限 |
| A5 | 审核中心 | P0 | 首发凭证审核（通过/驳回+原因）；数据补发审核（按规则定奖金额） |
| A6 | 奖励记录 | P1 | 全站奖励流水，标记「已发放」 |
| A7 | 数据看板 | P1 | 素材领取/提交/通过数、奖励支出汇总 |
| A8 | 素材上传 | P0 | 图片多张、视频、封面；本地磁盘存储 |

### 4.2 用户端（H5）

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| U1 | 登录 | P0 | 手机号+验证码（M1 可先邀请码/简化）；预留微信授权 |
| U2 | 分类浏览 | P0 | 首页展示一级分类 → 进入二级分类 |
| U3 | 任务大厅 | P0 | 分类下按标签筛选；素材卡片列表；**多选 1,2,3 一键领取** |
| U4 | 素材详情 | P0 | 文案一键复制、图片/视频查看保存、发布注意事项、领取按钮 |
| U5 | 我的任务 | P0 | 状态分组：待发布 / 待审核 / 可补数据 / 已完成 / 已过期 |
| U6 | 提交首发凭证 | P0 | 平台链接 + 发布截图（多图）；展示标签对应的发布引导 |
| U7 | 补发数据截图 | P1 | 达标后按轮次补交数据截图，显示规则档位与剩余轮次 |
| U8 | 奖励记录 | P1 | 每笔奖励金额、来源任务、状态 |

### 4.3 规则类需求

| 编号 | 规则 | 默认值 |
|------|------|--------|
| R1 | 每人每素材限领次数 | 1 次 |
| R2 | 素材领取总量配额 | 每素材可配，-1 不限 |
| R3 | 领取后须提交首发凭证的时限 | 48 小时，超时任务过期、释放配额 |
| R4 | 数据补发轮次上限 | 每素材可配，默认 0（不开启） |
| R5 | 同一发布链接全局唯一 | 是，重复提交拒绝 |
| R6 | 奖励金额精度 | 元，两位小数 |

## 5. 典型用例

### 用例 1：游戏-蛋仔派对 × 小红书（图文）

1. 运营创建一级分类「游戏」、二级分类「蛋仔派对」。
2. 新建素材《蛋仔派对夏日皮肤安利》：类型=图文，上传 3 图 + 文案；标签勾选「小红书」；首发奖励 3.00 元；数据规则：播放≥1000 奖 1.00、播放≥5000 奖 3.00（取最高）；补发上限 3 轮；配额 100。
3. 用户进入分类「游戏-蛋仔派对」，标签切到「小红书」，列表出现可用素材任务。
4. 用户勾选 1、2、3 号素材，点「领取所选」。
5. 逐个查看素材，复制文案、保存图片，页面展示引导：「打开小红书 APP 发布笔记 → 发布成功后截图」。
6. 用户发布成功后回到 H5，提交笔记链接 + 截图。
7. 运营审核通过 → 首发奖励 3.00 元入账。
8. 24 小时后播放量 6200，用户补发数据截图（第 1 轮）→ 审核通过 → 追加 3.00 元；之后最多再补 2 轮。

### 用例 2：影视-斗破苍穹 × 视频号（视频+文字）

同上，素材类型=视频+文字，标签=「视频号」，用户将视频发布到微信视频号；提交时填写视频号动态链接（或昵称+发布时间截图，视频号链接可复制性差，管理端备注栏人工核对）。

## 6. 非功能需求

- **规模假设**：素材 < 100 条、用户 < 1000、日任务 < 500 → **不引入 MySQL**，用 文件(md) + Redis 承载；素材超过 100 条或出现复杂关联查询时再升级（见 02/05 文档）。
- **部署**：单机（Nginx + PHP-FPM + Redis），一台 2C4G 可跑。
- **审核**：全人工审核，SLA 目标 24h 内处理完待审队列。
- **奖励发放**：本期记录金额并人工打款，通道（微信红包/支付宝）字段预留。
- **内容安全**：素材由运营录入，来源可控；用户上传仅截图，需校验类型/大小/数量。

## 7. 本期边界（明确不做）

- 不做自动代发（不对接任何平台发布 API，纯引导人工发布）。
- 不做平台数据自动抓取（播放/点赞数据以用户截图 + 人工审核为准）。
- 不做微信小程序端（H5 优先，后续可复用 API）。
- 不做多级分销、邀请裂变。
- 不做复杂风控（同设备/同图哈希的粗查重保留，详见 07 文档）。
