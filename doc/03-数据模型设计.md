# 03 数据模型设计

## 1. 实体关系总览

```
Category(一级) 1 ── n Category(二级) 1 ── n Material
                                        │ n : n
                                      Tag(渠道标签)      ← 素材预留多标签位
User 1 ── n Task n ── 1 Material
           │
           ├── n Submission（首发凭证 / 数据补发凭证）
           └── n Reward（奖励记录）
```

存储归属：`Category`、`Tag`、`Material` → md 文件（内容库）；`User`、`Task`、`Submission`、`Reward` → Redis（状态库）。Redis 键细节见 05 文档。

## 2. 分类 Category

两级固定结构，无更深层级。文件：`storage/categories.md`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | `cat_` + 4 位序号，如 `cat_1001` |
| name | string | 是 | 名称，如 `游戏`、`蛋仔派对` |
| parent_id | string | 是 | 一级为 `0`，二级挂一级 id |
| sort | int | 是 | 排序，小的在前 |
| status | enum | 是 | `on` / `off`，off 不在用户端展示 |

文件示例：

```markdown
---
categories:
  - {id: cat_1001, name: 游戏, parent_id: "0", sort: 1, status: on}
  - {id: cat_2001, name: 蛋仔派对, parent_id: cat_1001, sort: 1, status: on}
  - {id: cat_3001, name: 影视, parent_id: "0", sort: 2, status: on}
  - {id: cat_3002, name: 斗破苍穹, parent_id: cat_3001, sort: 1, status: on}
---
# 分类管理说明
- 删除二级分类前须先下架其下全部素材。
```

## 3. 标签 Tag

文件：`storage/tags.md`。当前语义 = **发布渠道**，`type` 字段预留扩展（如风格标签）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| key | string | 是 | slug，如 `xhs` / `sph` / `douyin`，素材引用它 |
| name | string | 是 | 展示名，如 `小红书` |
| type | enum | 是 | `channel`（渠道）/ `other`（预留） |
| guide | string | 否 | 发布引导文案，提交页展示给用户 |
| status | enum | 是 | `on` / `off` |

```markdown
---
tags:
  - {key: xhs,    name: 小红书,   type: channel, guide: "打开小红书APP发布图文笔记，发布成功后复制笔记链接并截图", status: on}
  - {key: sph,    name: 视频号,   type: channel, guide: "在微信-发现-视频号发布，提交时填写动态链接，链接无法复制时可填写昵称+发布时间并截图", status: on}
  - {key: douyin, name: 抖音,     type: channel, status: on}
  - {key: ks,     name: 快手,     type: channel, status: off}
  - {key: bili,   name: B站,      type: channel, status: on}
  - {key: wb,     name: 微博,     type: channel, status: on}
---
```

> 标签位说明：素材表单中「标签」是多选字段且**预留**——当前只用渠道类，后续若加「风格/活动」类标签，素材结构不用改，筛选时按 `tag.type` 区分展示。

## 4. 素材 Material（核心）

文件：`storage/materials/mat_XXXXX.md`，一素材一文件；frontmatter 为结构化字段，Markdown 正文为「发布说明/注意事项」，用户端详情页展示。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | `mat_` + 5 位自增（Redis seq 分配） |
| title | string | 是 | 标题 |
| type | enum | 是 | `image_text` 图文 / `video_text` 视频+文字 |
| category_id | string | 是 | **二级**分类 id |
| tag_keys | string[] | 是 | 标签 key 列表（预留多选位），≥1 个 |
| cover | string | 否 | 封面图 URL；缺省取 images[0] |
| images | string[] | type=图文 | 图片 URL 列表，≤9 张 |
| video | string | type=视频 | 视频 URL，单个 |
| text | string | 是 | 发布文案（纯文本，支持一键复制） |
| reward.first | decimal | 是 | 首发奖励，元 |
| reward.stats_rules | rule[] | 否 | 数据奖励档位，见下 |
| reward.stack_mode | enum | 否 | `highest`（默认，取最高命中档）/ `all`（命中叠加） |
| reward.max_bonus_rounds | int | 否 | 数据补发轮次上限，默认 0 |
| quota | int | 是 | 可领取总人数，-1 不限 |
| per_user_limit | int | 是 | 每人限领，默认 1 |
| window_hours | int | 否 | 领取后须在 N 小时内提交首发凭证，默认 48 |
| status | enum | 是 | `draft` / `published` / `offline` |
| created_at / updated_at | datetime | 是 | |

`stats_rules` 元素结构：`{metric: views|likes|comments, gte: int, reward: decimal}` —— 指标达阈值 `gte`，该轮补发可奖 `reward` 元。

文件示例：

```markdown
---
id: mat_10001
title: 蛋仔派对夏日皮肤安利
type: image_text
category_id: cat_2001
tag_keys: [xhs]
cover: /uploads/2026/10/01/a1b2c3.jpg
images:
  - /uploads/2026/10/01/a1b2c3.jpg
  - /uploads/2026/10/01/d4e5f6.jpg
  - /uploads/2026/10/01/g7h8i9.jpg
text: "夏天来了！蛋仔派对新出的果冻皮肤也太可爱了吧，姐妹们冲！#蛋仔派对 #夏日穿搭"
reward:
  first: 3.00
  stats_rules:
    - {metric: views, gte: 1000, reward: 1.00}
    - {metric: views, gte: 5000, reward: 3.00}
    - {metric: likes, gte: 100,  reward: 0.50}
  stack_mode: highest
  max_bonus_rounds: 3
quota: 100
per_user_limit: 1
window_hours: 48
status: published
created_at: 2026-10-01 12:00:00
updated_at: 2026-10-01 12:00:00
---
## 发布注意事项
- 必须带话题 #蛋仔派对
- 图片按顺序发布，不要自行加滤镜
```

## 5. 用户 User（Redis hash）

| 字段 | 类型 | 说明 |
|------|------|------|
| uid | string | `u_` + 6 位 |
| nickname / avatar | string | 注册时生成默认值 |
| phone | string | 登录手机号 |
| wx_openid | string | 预留 |
| status | enum | `normal` / `banned` |
| total_reward | decimal | 累计奖励（冗余，便于展示） |
| created_at | datetime | |

## 6. 任务 Task（Redis hash，键 `sc:task:{tid}`）

任务 = 用户 × 素材的一次领取实例，是全系统的状态中枢。

| 字段 | 类型 | 说明 |
|------|------|------|
| task_id | string | `t_` + 8 位 |
| user_id / material_id / category_id / tag_key | string | 冗余 denormalize，避免查询回表；tag_key 记录用户以哪个渠道标签领取 |
| status | enum | 状态机见 §9 |
| platform_url | string | 用户提交的发布链接 |
| claim_at / submit_at / review_at | datetime | 关键时间 |
| deadline_at | datetime | 首发凭证提交截止（claim_at + window_hours） |
| bonus_round | int | 已通过的数据补发轮次 |
| bonus_paid | decimal | 数据奖励累计 |
| first_reward | decimal | 首发奖励金额（审核通过时按素材当时规则落定） |
| total_reward | decimal | first_reward + bonus_paid |
| last_reject_reason | string | 最近一次驳回原因 |

## 7. 凭证 Submission（Redis hash，键 `sc:sub:{sid}`）

| 字段 | 类型 | 说明 |
|------|------|------|
| sub_id | string | `s_` + 8 位 |
| task_id / user_id / material_id | string | 归属 |
| type | enum | `first` 首发 / `stats` 数据补发 |
| round | int | type=stats 时的轮次（1 起） |
| platform_url | string | type=first 必填 |
| screenshots | string[] | 截图 URL 列表，1~3 张 |
| metrics | hash-in-json | type=stats：`{views,likes,comments}` 用户自报（截图为准） |
| reward_snapshot | string(JSON) | 凭证创建时素材奖励规则快照，审核核算以此为准（防素材中途改规则） |
| status | enum | `pending` / `approved` / `rejected` |
| reward_amount | decimal | 审核通过时核定的本笔奖励 |
| reviewer / reason | string | 审核人、驳回原因 |
| created_at / reviewed_at | datetime | |

## 8. 奖励 Reward（Redis zset + hash）

- 流水：`sc:reward:{uid}` zset，member = `r_{rid}`，score = 时间戳；明细 hash `sc:reward:detail:{rid}`：

| 字段 | 说明 |
|------|------|
| rid / user_id / task_id / sub_id | 归属 |
| type | `first` / `stats` |
| amount | 金额 |
| status | `granted`（已入账）/ `paid`（已打款，人工标记） |
| created_at / paid_at | 时间 |

## 9. 状态机

### 9.1 任务状态

```
claimed(已领取)
   │ 用户提交首发凭证
   ▼
submitted(待审核) ──驳回──▶ claimed(可重新提交, deadline 不变)
   │ 审核通过
   ▼
approved(已通过,首发奖励入账)
   │ 素材配了 stats_rules 且轮次未满            │ 未配数据奖励
   ▼                                            ▼
bonus_open(可补数据) ──提交──▶ bonus_pending ──通过──▶ bonus_open(轮次+1)
   │                                │                    │ 轮次满
   │ 轮次满                          │驳回→bonus_open     ▼
   └────────────▶ finished(已完成) ◀────────────────────┘

claimed ──超时未提交──▶ expired(已过期, 释放配额)
```

| 当前状态 | 事件 | 动作 | 次状态 |
|----------|------|------|--------|
| claimed | submit 首发凭证 | 建Submission、链接去重 | submitted |
| submitted | 审核驳回 | 记原因，通知 | claimed |
| submitted | 审核通过 | 发首发奖励；若 max_bonus_rounds>0 进 bonus_open，否则 finished | approved → bonus_open/finished |
| bonus_open | 提交数据截图 | 建Submission(round+1) | bonus_pending |
| bonus_pending | 审核通过 | 按规则核奖、入账、round+1 | bonus_open / finished |
| claimed | deadline 超时 | 释放配额 quota+1 | expired |

### 9.2 Submission 状态

`pending → approved / rejected`（终态，驳回后是重新提交生成新 Submission，不做状态回退）。

## 10. 数据校验要点（写入前）

- 素材：`type=image_text` 时 images 必填 1~9 张；`type=video_text` 时 video 必填；tag_keys 必须是存在的 `on` 状态标签。
- 提交首发凭证：URL 格式校验；截图 1~3 张。
- 数据补发：round ≤ max_bonus_rounds；上轮 bonus_pending 未审完不允许再交。
